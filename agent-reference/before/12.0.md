## 摘要
本阶段新增针对异常情况的处理。包括：增加失败重试、增加因异常情况导致文件未继续执行的扫描操作、增加防倒退机制、增加文件过期操作

## 目标步骤
1. 加入防倒退机制，前后端配合保护新进度不小于旧进度，保护因网络情况旧信息错误覆盖新信息的情况
    - 在 export_jobs / export_job_attempt 表中，加入 job_version 字段，每次任务开始执行时，从1计算，当每次成功写入文件回写状态时，先扫出当前 job_version 值，递增的形式加载新的动作中。
    - 前端在轮训时，判断接口返回 job_version 如果比当前的大进行进度更新，反之拦截

2. 增加失败状态重试接口
    - 仅在 FAILED 状态允许重试操作
    - 前端新增重试接口请求操作，页面也增加重试操作按钮
    - 关键信息：前端触发重试申请时，重新进入 outbox 模式推进任务，并且旧 attempt 信息归档保留不允许修改
    
3. 状态机增加过期状态，EXPIRED状态
    - 仅允许 SUCCESS 状态流转至 EXPIRED 状态
    - 导出任务成功生成时，新加字段“过期时间”，逻辑是生成成功的时间 24小时后过期
    - 增加定时任务，每一个小时执行一次扫描，超过过期时间的 SUCCESS 状态 job ，删除成功的 .xlsx 文件，并将状态流转至 EXPIRED，遵循先删除文件，再进行状态回写

4. 孤儿文件的处理
    - 针对写入文件过程中，workbook突然挂了的情况
        - 表字段加入心跳时间：表示最近一次操作的时间
        - 表字段加入租约时间：在心跳时间的基础上加5分钟
        - 当批次查询成功，并成功写入文件后触发字段更新，2个字段是同步往前写入
        - 扫描 RUNNING 状态的任务，如出现无租约时间、或租约时间已过期的情况，设置为 FAILED 状态，如出现临时文件进行删除
    - 已完成的场景：
        - 原子生成失败的 .tmp 临时文件删除
        - 未登记数据库的 .xlsx 文件删除

## 注意事项
- 暂不加入 redis、SSE 的新技术
- 每一个环节都判断是否有联动反应
