## 本阶段需求摘要
完善文件生成的整个流程，保留不提供下载等操作的方案

## 目标步骤
1. 沿用已实现的 SXSSF 流式写入文件的模式，其中文本格式增加优化
    - 针对金额的单元格，默认格式化为文本格式，如果是整数的数值，填充至小数点后2位 `.00` 的形式
    - 针对时间的单元格，转换为格式化后的文本格式
2. 写入文件的每一列，都需要是数据库中的提供出来表格可导出的白名单，如遇到特殊渠道写入的导出任务，有不是白名单的字段自动失败任务
3. 文件的路径，加入安全校验，root部分使用配置文件管理，当写入、清理、以及后续的下载动作都需校验是否在受控路径下，避免路径指向到安全文件夹以外的路径
    - 文件路径的文件夹常见，考虑根据任务隔开互相独立不打扰
4. 更新生成文件的流转，文件写入后生成项目内部的 .tmp 临时文件，当 workbook 全部写入完毕 close后，可考虑利用 java NIO 插件，原子发布对外提供的 .xlsx文件
    - 原子流转成功后，删除 .tmp 临时文件，并回写 export_jobs/export_job_attempt 的任务字段（包括状态、文件相对路径、文件大小、任务完成时间）
    - 原子流转失败，删除 .tmp 临时文件，并回写失败状态
    - 原子流转成功，但回写状态失败，也属于失败，删除 .tmp 临时文件、.xlsx文件
    （可考虑 .tmp临时文件和 .xlsx放在同一个文件夹目录下）
