作为前端工程师，第一次创建全栈项目，目前前后端的框架已确定。


本阶段的目标有以下几方面

前端部分：
1. 筛选条件增加排序功能，支持按照金额、按照创建时间的升序、降序的排列
2. 手选模式、全选的反选模式，最多只支持选择100条，在上方的选择提示语中加入提示文案。（当选择达到上限时，不允许再被勾选，并给 toast 提示文案）
3. 顶部导出已选按钮，当有选中数据时，加入选中条数的提醒： 导出已选 （*）

后端部分：
1. 实现稳定分页，例如遇到金额、创建时间相同时，结合自动递增的id 作为第二排序键
    - 加入筛选条件白名单，当有白名单以外的非法值会拦截报错，并有清晰的错误文案（例如：排序的参数值是升序、降序以外的）
2. 将 mysql 的数据库表，放入 /backend/resources 中
    - 现有的数据库表只保留 schema 和 DDL 命令，将原有的 DML 命令清除，保留空数据。
    - 制作额外的数据库脚本，支持插入10000条对应格式的有规律但随机的数据
    - 引入 flyway 作为本次执行后，后续的变更可做版本最终的工具
3. 将当前接口响应的 JSON envelope 作为规范，后续再次基础上做增加
4. 在响应前端接口时，加入一个 traceId 的 filter，并使用 MDC 存储当前的 traceId，用做后续的日志链路追踪使用，
    - filter中判断 如果 MDC 中有 traceId，取出使用
    - filter中判断 如果 MDC 中没有 traceId， 则新增一个 UUID 增加在 JSON envelop中 和 响应头 `x-trace-id` 中一并返回
