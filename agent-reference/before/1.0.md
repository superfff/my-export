### 概要
搭建一个全新的列表查询、列表导出的后台管理系统。

### 需求
一共2个功能模块，订单管理、导出管理，左侧是目录区域，右侧是占满的功能模块区域（没有固定的布局代码实现方式，使用热门的方案）。这个后台系统设置为不滚动，由功能模块内部自行内容区域滚动

1. 订单管理

提供订单号、客户名称、客户手机号、状态状态、订单创建时间的信息信息查询，以及对应字段的筛选查询

- 字段说明：
  - 订单状态暂定：未支付、已支付、已取消 3种状态

- 界面：
  - 顶部有目录的标题
  - 然后查询条件
  - 表格区域默认占满，内容超出时滚动
  - 底部有分页器


2. 导出管理

这一个版本暂时不和订单管理进行联动，先进行页面搭建。单纯提供表格区域，包括了导出任务id、文件名、导出条数、状态、导出进度、创建时间、完成时间、文件大小。

- 界面：
  - 提供表格对上述字段进行展示，默认占满，内容超出时滚动
  - 底部有分页器

### 代码规范
使用清晰的文件夹目录结构，如果有涉及到重复的业务组件，使用 `/components/` 文件夹，如果有重复的代码，提取到 `/utils`，第一个版本暂时不考虑请求，无需额外创建，先加入 mock 的形式有模拟数据


### 技术栈
使用 react + antd 的技术栈搭建，暂时只进行前端搭建，先不考虑后端的相关逻辑，目前以实用的技术实现为主，无需很酷的技术

- react 技术栈无需引入 redux、zustand的状态管理，路由使用原生 API popState、pushState 实现，无需引入 react-router
- antd 使用最小化按需引入
- 样式使用 css module 的形式即可，与页面模块放在同一文件夹中
- 使用 mock 创建 60条订单，3种状态各种20条，mock时按照状态 123/123的循环创建，订单创建时间就按照命令发下的时候来参照
- 使用 pnpm 进行依赖包的管理
