# 阶段 6.0 完整实施提示语

> 来源：`agent-reference/before/6.0.md`
> 用途：可直接投喂给后续编码会话，指导其实现"异步导出任务发起 + 持久化 + 幂等去重"。
> 性质：仅实施蓝图，本文档不包含代码，也未被代码编辑过。

## 一、背景与目标

全栈订单导出项目，仓库结构 `frontend/`（React18 + Vite + TS + AntD5 + pnpm）+ `backend/`（SpringBoot3 + Java21 + MyBatis-Plus + Flyway）+ MySQL。当前进度：

- 订单页已具备双模式勾选（手动 / 全选排除，上限 100）、排序 / 筛选 / 稳定分页、`导出已选` / `导出筛选结果` 按钮与 `ExportModal` 弹窗（当前仅内存拼接 `ExportParams` 后 `console.log`，**未发真实请求**）。
- 后端仅有 `GET /api/order`（`OrderController`），已规范 JSON envelope（`ApiResponse{code,message,data,traceId}`，`code=0` 成功）、`TraceIdFilter`、`GlobalExceptionHandler`（`IllegalArgumentException` → HTTP 200 + `code=400`）、Flyway `V1__create_t_order.sql`。

**本阶段目标**：打通"前端异步导出任务发起 → 后端接收入库 → `export_jobs` 持久化"链路，含幂等 Key 意图保护与快照 `request_hash` 去重判别，**为后续"导出中心 / 真正导出"打底**。本阶段**不引入新技术**。

**明确本期不做（防止实现越界）**：

- 不真正生成 / 导出文件；
- 不对订单行做分页拉取 / 导出；本期仅在建任务时对订单库做一次 `count(*)` / `max(id)` 聚合，用于落 `expected_total`（统计总条数）与 `max_order_id`（最大订单 id）两个快照列，为导出中心 / 真正导出打底；
- 不引入任何异步 worker / 线程池 / 消息队列；
- `RUNNING / SUCCESS / FAILED` 只作为状态字段合法枚举存在，本期插入后任务停留在 `PENDING`，**没有任何代码路径推进状态**；
- 不做导出中心 / 任务列表查询页；
- 不改动现有选择模型与 100 条上限规则。

## 二、接口契约（前后端一致）

### 端点

```
POST /api/export-job
Headers:
  Content-Type: application/json
  Idempotency-Key: <string 必填，UUIDv4，长度 ≤64>
```

- 以 RESTful 资源 `export-job` 独立搭建（`ExportJobController`，`@RequestMapping("/api/export-job")`），**不沿用订单列表接口 `GET /api/order`**。

### 请求体（与前端 `ExportParams` 对齐）

```jsonc
{
  "filename": "订单导出_20260903",        // string 必填，trim 后非空，≤255
  "fields": ["orderNo","customerName","phone","amount","status","createdAt"], // 必填，非空，值∈白名单
  "mode": "FILTERED",                     // 必填 ∈ {FILTERED, SELECTED, ALL_EXCLUDE}
  "query": { /* 仅筛选条件，见下 */ },       // FILTERED / ALL_EXCLUDE 生效；谓词字段见下
  "selectedIds": [1,2,3],                 // 仅 SELECTED，非空，≤100
  "excludedIds": [4,5]                    // 仅 ALL_EXCLUDE，≤100，可空
}
```

- 三种场景映射：
  - **导出筛选结果** → `FILTERED`（query = 当前筛选，导出全部命中数据）；
  - **导出已选 · 手动勾选** → `SELECTED`（selectedIds = 勾选 id）；
  - **导出已选 · 全选反选** → `ALL_EXCLUDE`（query = 筛选 + excludedIds = 反选 id）。
- `query` 只承载筛选谓词，由本次 `/export-job` 请求体**独立声明**：`orderNo / customerName / phone / status / startTime / endTime`（字符串模糊 / 精确匹配含义与订单页筛选字段一致，时间为毫秒时间戳）。**不沿用 / 复用 `GET /api/order` 接口**：不调用它、不绑定其 `OrderQueryDTO` 查询参数 / 分页字段做导出拼装；`page / pageSize / sortField / sortOrder` 不参与、后端忽略（排序与分页不影响"导出的行集合"）。

### 响应

成功：

```jsonc
// HTTP 200
{ "code": 0, "message": "ok", "data": { "id": 12, "filename": "...", "exportMode": "FILTERED",
  "status": "PENDING", "expectedTotal": 1234, "maxOrderId": 98765,
  "createdAt": "2026-09-03T10:00:00" }, "traceId": "..." }
```

幂等重复（**一律 409**）：

```jsonc
// HTTP 409，envelope.code = 409
// request_hash 相同：
{ "code": 409, "message": "已有相同导出任务", "data": null, "traceId": "..." }
// request_hash 不同：
{ "code": 409, "message": "幂等值冲突", "data": null, "traceId": "..." }
```

校验失败：`HTTP 400` + `envelope.code=400`，`message` 为清晰文案（见第六节）。以上 409 / 400 需用**真正的 HTTP 状态码**返回（引入导出专用异常与 handler，可返回 `ResponseEntity`），同时**不得回归** `GET /api/order` 现有"HTTP 200 + code=400"的行为。

## 三、幂等语义与前端成功判定（已确认：严格 409）

- 后端以 `Idempotency-Key` 作为导出意图的唯一标识，`export_jobs.idempotency_key` 建**唯一索引**。
- 新 Key → 校验通过即入库（状态 `PENDING`）。
- 已存在该 Key → **拒绝入库，一律 409**：比对已存在行的 `request_hash` 与本次计算值：相同 → `已有相同导出任务`；不同 → `幂等值冲突`。
- 并发兜底：同一 Key 两个请求同时穿过查重时，依赖唯一索引，捕获 `DuplicateKeyException` 后重查已有行并按上述规则返回 409。
- **前端判定**：把 `code === 409 && message === '已有相同导出任务'` 当作**本次提交成功**（覆盖"首次其实已入库、仅响应丢失后重试"的场景）→ 消费 Key、关闭弹窗、提示"已创建导出任务"；`code === 409 && message === '幂等值冲突'` 当作异常 → 提示并废弃当前 Key（正常 Key 生命周期下不应发生）。

## 四、`request_hash` 计算规则（仅后端计算）

`request_hash` 是**导出内容指纹**，用于区分两种 409。**不包含**：导出任务自增 id（`export_jobs.id`，插入前不存在）、两个聚合快照列（`expected_total` / `max_order_id`，均可由范围谓词推导，计入无意义）、文件名、幂等 Key、排序、分页。规范化输入保证"相同请求体 → 相同 hash"：

1. `fields`：trim 后排序去重，逗号连接成 `fieldsCsv`。
2. `query`：按固定键序 `orderNo, customerName, phone, status, startTime, endTime` 取非空项拼 `k=v`，`&` 连接（字符串值 trim；时间为毫秒数字）。若全空则 scope 中 query 记为空串。
3. scope 按 mode 规范化：
   - `FILTERED`：`mode|query`
   - `ALL_EXCLUDE`：`mode|query|excludedIds`（id 排序去重，逗号连接）
   - `SELECTED`：`mode|selectedIds`（id 排序去重，逗号连接）
4. `hashInput = fieldsCsv + '#' + scopeStr`（mode 已含在 scopeStr 内）。
5. `request_hash = SHA-256(hashInput)` 的小写 hex（`CHAR(64)`）。

`request_hash` 只建普通索引（同内容换新 Key 再次导出是"用户新的明确意图"，允许生成第二个 job；去重门禁是幂等 Key）。

## 五、`export_jobs` 表（Flyway `V2__create_export_jobs.sql`）

```sql
CREATE TABLE IF NOT EXISTS export_jobs (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    idempotency_key VARCHAR(64)    NOT NULL COMMENT '幂等键(UUIDv4)，意图唯一',
    request_hash    CHAR(64)       NOT NULL COMMENT '导出内容指纹:sha256(规范化列+范围)，不含文件名/幂等键/jobId',
    export_mode     VARCHAR(16)    NOT NULL COMMENT '导出场景:SELECTED/ALL_EXCLUDE/FILTERED',
    status          VARCHAR(16)    NOT NULL DEFAULT 'PENDING' COMMENT '状态机:PENDING/RUNNING/SUCCESS/FAILED',
    filename        VARCHAR(255)   NOT NULL COMMENT '导出文件名',
    export_columns  VARCHAR(1000)  NOT NULL COMMENT '勾选导出列(JSON数组，保留用户选择顺序)',
    scope_snapshot  TEXT           NOT NULL COMMENT '导出范围快照(规范化JSON:mode+query+ids)',
    expected_total  BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '统计总条数:创建时按本任务筛选/范围对t_order聚合的命中订单总数(供导出中心展示/后续导出进度分母)',
    max_order_id    BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '最大订单id:创建时命中订单的最大t_order.id(即用户语境"当前查询条件下最大的jobId"，一致性水位，后续导出按 id<=该值 防漂移)',
    created_at      DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_idempotency_key (idempotency_key),
    KEY idx_request_hash (request_hash),
    KEY idx_status (status)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '异步导出任务表';
```

状态机：后端定义 `ExportJobStatus` 枚举（`PENDING / RUNNING / SUCCESS / FAILED`），DB 存字符串；插入恒为 `PENDING`。

**两个快照列（`expected_total` / `max_order_id`）**：创建导出任务时，后端按本任务"会导出的行集合"对订单库实时聚合 `count(*)` 与 `max(id)` 后写入（`jobId` 即命中订单的 `t_order.id`）。它们只用于导出中心展示与后续真正导出的进度分母 / 一致性水位：**不参与 `request_hash`、不参与幂等判别**（同内容换新 Key 再次导出时，两次创建之间订单库可能已变化，各自按当时快照取值即可）。

## 六、后端实施（新增 / 修改清单）

按 MVC 分层，建议包结构沿用 `com.example.order`：

- `entity/ExportJob.java`、`mapper/ExportJobMapper.java`（extends BaseMapper）；
- `dto/ExportCreateRequest.java`（含嵌套的 query 记录）、`dto/ExportJobVO.java`（字段含 `id / filename / exportMode / status / expectedTotal / maxOrderId / createdAt`）；
- `service/ExportJobService` + `impl/ExportJobServiceImpl`；
- `controller/ExportJobController.java`：RESTful `POST /api/export-job`（`@RequestMapping("/api/export-job")`）；
- `common`：导出校验 / 幂等冲突专用异常（携带 code 400 / 409），并在 `GlobalExceptionHandler` 增加 handler 使其返回**对应 HTTP 状态 + envelope**（不动 `IllegalArgumentException` 现有处理，避免回归）；
- `resources/db/migration/V2__create_export_jobs.sql`（见第五节）。

`ExportJobServiceImpl.create(request, idempotencyKey)` 流程：

1. 校验 → 不合规抛 400（文案见"校验规则"小节）。
2. 计算 `request_hash`（第四节规则）。
3. 按 `idempotency_key` 查重：已存在 → 比较 hash 返回对应 409。
4. 按本任务"会导出的行集合"对订单库做一次只读聚合：`count(*)` → `expected_total`、`max(id)` → `max_order_id`：
   - 行集合谓词：`FILTERED` = 仅 `query`；`ALL_EXCLUDE` = `query` 再排除 `excludedIds`；`SELECTED` = `id ∈ selectedIds`。
   - **走订单数据访问层（`OrderMapper` 新增按谓词 `count(*)` / `max(id)` 聚合方法，复用同一套条件拼装），绝不复用 / 调用 HTTP `GET /api/order` 列表接口**。
5. 组装并 `insert`，状态 `PENDING`，落 `expected_total` / `max_order_id`，`scope_snapshot` / `export_columns` 存规范化 JSON。
6. 捕获并发 `DuplicateKeyException` → 重查并按第 3 步逻辑返回 409。
7. 返回 `ExportJobVO`（含 `expectedTotal` / `maxOrderId`）。

校验规则（400，均清晰文案）：

- Header `Idempotency-Key` 缺失 / 空白 / 超 64 → `缺少幂等键 Idempotency-Key`；
- `filename` trim 后空或超 255；
- `fields` 空数组，或含白名单外字段（白名单 = `orderNo, customerName, phone, amount, status, createdAt`）；
- `mode` 非法；
- `SELECTED` 无 `selectedIds`、为空或 >100；
- `ALL_EXCLUDE` 的 `excludedIds` >100；
- **明确选择**：多余字段一律忽略，不做强拒绝，仅校验必填 / 白名单。

### 幂等 Key 生命周期（前端，用 `useRef` 持有"进行中的导出意图"）

一条"导出意图会话" = 打开弹窗 → 提交成功（或冲突作废）。

- **打开弹窗**（`导出已选` / `导出筛选结果`）、**查询 / 重置 / 勾选变化**（`handleSearch` / `handleReset` / `handleSelectionChange`）时：若上一意图已结束则清空 `pending = { key, sig }`（勾选 / 筛选变化会使导出内容变，旧 Key 作废）。
- **首次确认提交**：`key = crypto.randomUUID()`（**非 `crypto.uuid`**），计算本次请求体的 `sig`（规范化 JSON 字符串），存 `pending`。
- **重试**（网络失败 / 超时 / HTTP≥500 / 非 409 错误，且弹窗未关、内容未变）：`sig` 一致 → 复用同一 Key 重发。
- **同一会话内改动内容再提交**（改文件名 / 字段后重发）：`sig` 变化 → 重新生成 Key。
- **结果分支**：
  - `code = 0` → 成功，消费 Key（清空 pending），关闭弹窗 + 成功提示；
  - `409 && "已有相同导出任务"` → 同成功处理；
  - `409 && "幂等值冲突"` → 错误提示并废弃 pending（重新生成）；
  - 其余错误 / 超时 → 保留 pending，toast，可重试。
- 判定用的两条 409 文案在前后端各定义为**常量**、逐字一致，避免手写散落。
